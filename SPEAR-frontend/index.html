S.P.E.A.R / AWARENESS

Understand the email signals

Indicators help you decide what to verify. They are clues, not proof on their own.

01

SPF

Sender Policy Framework reports whether the sending server is authorized by a domain. This project only reads a result already present in the email header.

02

DKIM

DomainKeys Identified Mail uses a cryptographic signature. This project does not verify the signature; it displays the reported Authentication-Results value.

03

DMARC

DMARC uses SPF/DKIM alignment and a domain policy. A result may be missing from a message and needs context.

04

Links and urgency

Unexpected destinations, requests for credentials, and time pressure deserve extra care. Open important services through a known address.

If an email seems suspiciousDo not open unexpected attachments or reply with sensitive information. Verify unusual requests through a known, independent channel.
PROJECT OVERVIEW

S.P.E.A.R

Spoofing Protection, Email Analysis & Review — an educational project demo for inspecting email evidence.

⌕

Local by design

Uploaded email files are parsed in memory; the original file is not saved. A derived analysis report is saved in a local SQLite database.

⚑

Know the limits

This is a heuristic review, not a malware scanner or a mail-provider verdict. It does not perform DNS lookups, verify DKIM signatures, resolve links, or establish that an email is safe.
